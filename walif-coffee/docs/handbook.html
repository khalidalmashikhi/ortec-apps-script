وليف كوفي — النظام المالي والتشغيلي

دليل آلية النظام، الروابط، وطريقة نقله وتثبيته لزبائن آخرين (نسخة Cafe Books القابلة لإعادة البيع)
الإصدار 1.3 · سبتمبر 2026 · Google Apps Script + Google Sheets + Google Drive

1. ما هو النظام

نظام محاسبي وتشغيلي مبسّط لمحلات القهوة يعمل بالكامل داخل حساب Google الخاص بالمالك، بلا خوادم ولا اشتراكات. يستورد مبيعات نظام الكاشير Loyverse من ملف CSV، ويُسجّل المشتريات والمصروفات والرواتب والإيجار مع صور الإيصالات، ويحسب الربح والخسارة والحركة النقدية، ويُصدر تقارير PDF، ويرسل تقريرًا يوميًا بالبريد. الواجهة عربية/إنجليزية وتعمل على الهاتف والكمبيوتر.

2. مكوّنات النظام وأين تعيش البيانات

الواجهة (Web App)صفحة ويب منشورة من Apps Script، تُفتح من أي متصفح أو تُضاف إلى شاشة الهاتف كتطبيق.
قاعدة البياناتملف Google Sheets واحد يحتوي 11 ورقة: Sales_Raw، Sales_Imports، Purchases، Expenses، Payroll، Rent، Users، Settings، Audit_Log، Error_Log، Dashboard_Data.
المرفقات والتقاريرمجلد في Google Drive باسم "<اسم المحل> Accounting" وفيه Invoices/السنة/الشهر وReports/السنة/الشهر.
كلمات المرور والجلساتScript Properties (لا تُخزَّن في الجدول): Hash + Salt لكلمات المرور، ورموز جلسات عشوائية تنتهي بعد 8 ساعات.
الكود المصدريمستودع GitHub، مجلد walif-coffee (20 ملف خادم .gs و6 ملفات واجهة .html + المثبّت وأدوات الاختبار).

4. آلية العمل اليومية

أ. المحاسب

  1. تصدير تقرير المبيعات بالأصناف من Loyverse بصيغة CSV (الأعمدة الـ22 القياسية).
  2. رفع الملف → "فحص الملف": يظهر الفترة، عدد الصفوف، الفواتير الفريدة، الكمية، الإجمالي، الخصومات، الصافي، تكلفة البضاعة، الربح، الضرائب، والصفوف المرفوضة والمكررة.
  3. "اعتماد واستيراد": يُحفظ فقط الجديد. مفتاح التكرار: Store + Receipt number + Date + SKU + Item + Quantity + Net sales. رفع الملف نفسه مرة أخرى يستورد صفرًا.
  4. تسجيل فاتورة المشتريات (رقم، تاريخ، مورد، تصنيف، مبالغ، طريقة وحالة الدفع، هل هي مخزون) مع تصوير الإيصال من كاميرا الهاتف. الفاتورة المكررة (نفس المورد والرقم والتاريخ والإجمالي) تُرفض.
  5. تسجيل المصروف، الراتب (الصافي = الأساسي + البدل + الإضافي − الخصم − السلفة)، والإيجار.

ب. المدير

  • 14 بطاقة مؤشرات، فلاتر (اليوم/أمس/7 أيام/الشهر/الشهر السابق/فترة مخصصة، الفرع، POS، الكاشير، التصنيف، الصنف)، 15 جدولًا، 6 رسوم بيانية.
  • 11 نوع تقرير PDF: يومي، أسبوعي، شهري، فترة مخصصة، مشتريات، مصروفات، رواتب، إيجارات، ربح وخسارة، حركة نقدية، أرشيف الإيصالات بالصور.
  • التقرير اليومي بالبريد تلقائيًا (الساعة قابلة للضبط، تقرير اليوم السابق كاملًا افتراضيًا) مع PDF مرفق وملخص في نص الرسالة.
  • تعديل أو إلغاء أي سجل مع تسجيل السبب؛ لا حذف نهائي (ACTIVE / CANCELLED).
  • سجل العمليات: الدخول الناجح والفاشل، الرفع، الاستيراد، الإضافة، التعديل، الإلغاء، التقارير، البريد، الإعدادات.

5. القواعد المالية

قائمة الربح والخسارة: صافي المبيعات (Net sales) − تكلفة البضاعة المباعة (Cost of goods من Loyverse) = مجمل الربح، مع مطابقته بمجمل ربح Loyverse. صافي الربح التشغيلي = مجمل الربح − (المصروفات + الرواتب + الإيجار). فواتير المخزون لا تُخصم مرة ثانية لأن تكلفة الجزء المباع منها داخل Cost of goods.

الحركة النقدية: صافي المبيعات − المشتريات المدفوعة − المصروفات المدفوعة − الرواتب المدفوعة − الإيجار المدفوع. الفرق بين الربح والنقد يُعرض صراحة في لوحة المدير.

المرتجعات تُسجَّل بالسالب؛ الفواتير الملغاة (Cancelled/Void) تُرفض عند الاستيراد. العملة الافتراضية OMR بثلاث منازل عشرية، والتوقيت Asia/Muscat.

7. النسخة القابلة لإعادة البيع (Cafe Books)

الكود واحد لكل الزبائن. الهوية تُضبط من داخل النظام (الإعدادات → هوية المحل): الاسم بالعربية والإنجليزية، كلمة الشعار بالحرفين، السطر الصغير، اللونان، رمز العملة، أو رابط صورة شعار. تنعكس على صفحة الدخول والشريط العلوي وتقارير PDF والبريد وأسماء الملفات ومجلد Drive. الافتراضي العام "Cafe Books / دفاتر الكافيه" بدون بريد ولا بيانات.

القالب الرئيسي (لا يُستخدم مباشرة، يُنسخ)https://docs.google.com/spreadsheets/d/1Dsu0PZW_TvavfA2MX7RU-JDnnljtqENdQQt_68LpqQ4/edit
مشروع Apps Script للقالبhttps://script.google.com/home/projects/1VyEBzQPV4FumhDPoWIsvqbP6VTkch9SWUhBNHjeFuw8gDas23nqS_pbc/edit

خطوات تثبيت نسخة لزبون جديد (نحو 5 دقائق)

  1. افتح القالب الرئيسي → File → Make a copy → سمِّها باسم الزبون (مثل "Bean Bar Accounting").
    لتكون النسخة في حساب الزبون نفسه: شارك القالب معه (Viewer يكفي) ليعمل هو "Make a copy" من حسابه؛ الكود يُنسخ مع الملف تلقائيًا.
  2. في النسخة: Extensions → Apps Script → Deploy → New deployment → النوع Web app → Execute as: Me → Who has access: Anyone → Deploy → انسخ رابط /exec.
  3. افتح الرابط ووافق على الصلاحيات مرة واحدة (Sheets, Drive, Docs, Gmail). تُبنى الأوراق والمجلدات والحسابات تلقائيًا خلال نصف دقيقة.
  4. ادخل admin / 2026 → الإعدادات → هوية المحل → احفظ. ثم بريد التقرير اليومي وساعته → احفظ (يُنشأ المشغّل تلقائيًا). ثم غيّر كلمتي المرور.
  5. سلّم الزبون: رابط النظام، اسمي المستخدم وكلمتي المرور، ورابط ملف Sheets (اختياري).

نقل نسخة قائمة إلى حساب آخر: افتح ملف Sheets → File → Make a copy إلى الحساب الجديد (أو شاركه ثم انسخه من هناك). النسخة تحمل الكود والبيانات؛ يلزم فقط نشر Web App جديد من الحساب الجديد (الخطوتان 2 و3) وإعادة إدخال كلمات المرور (لأنها في Script Properties ولا تُنسخ). المرفقات القديمة تبقى في Drive الحساب الأصلي بروابطها.

تحديث الكود لاحقًا لكل الزبائن

  • الطريقة الأسهل للزبون: من محرر Apps Script الخاص به يلصق ملف installer/Installer.gs في Code.gs ومحتوى installer/appsscript.json في المانيفست، يشغّل installWalifCoffee (بعد تفعيل Apps Script API من script.google.com/home/usersettings)، ثم Deploy → Manage deployments → New version.
  • الطريقة الأسرع لك: clasp push بمعرّف مشروع كل زبون (ملف .clasp.json)، ثم clasp deploy -i <deploymentId> ليبقى الرابط نفسه.
  • التحديث لا يمس البيانات ولا الهوية ولا كلمات المرور.

8. الحدود والملاحظات التشغيلية

  • كل نسخة تعمل بحصص Google المجانية لحساب مالكها: نحو 100 رسالة بريد يوميًا لحساب Gmail، و6 دقائق كحد أقصى لكل تنفيذ. الاستيراد المعتاد (آلاف الصفوف) يستغرق ثوانٍ.
  • المرفقات: PDF أو JPG أو PNG بحد 5 ميغابايت للملف.
  • تقرير أرشيف الإيصالات يدرج حتى 60 صورة في الملف الواحد؛ ملفات PDF المرفقة تظهر بروابطها فقط.
  • الوصول "Anyone" يعني أن الرابط يفتح صفحة الدخول لأي شخص يملكه، والحماية بكلمات المرور داخل النظام؛ لذلك غيّر الكلمات الافتراضية ولا تشارك الرابط إلا مع المستخدمين.
  • النسخ الاحتياطي: ملف Sheets يحتفظ بسجل الإصدارات (File → Version history)، ويمكن عمل نسخة دورية بـ Make a copy.
